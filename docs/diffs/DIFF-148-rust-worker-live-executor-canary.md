# DIFF-148: Rust Worker Live Executor Canary

Status: Locked

## Type

Change-bearing Rust worker canary gate and side-effect verification planning.

## Objective

Add a narrowly scoped live-execution canary path for the Rust worker without
replacing Python/Celery worker process ownership.

Decision:

- Add an explicit one-job canary gate.
- Keep default worker command safe and non-mutating.
- Keep all real DB, audit, artifact, and Qdrant side effects planned-only in
  this DIFF.
- Keep Python/Celery `worker` active.
- Keep Python/Celery `beat` active.
- Do not remove `services/worker/`.
- Do not remove `worker` or `beat` from Docker Compose.
- Do not claim full Rust-only repository or runtime operation.

## Baseline Facts

- DIFF-147 added the Rust worker runtime harness.
- Rust API path is complete.
- FastAPI fallback is removed.
- `services/api/` is archived.
- Rust worker parity contracts cover:
  - `collection_normalization`
  - `document_chunking`
  - `chunk_vector_upsert`
- Python/Celery `worker` and `beat` remain active.

## Implementation Notes

DIFF-148 extends `igy6-worker` with an explicit canary gate:

```bash
cargo run -p igy6-worker -- --once --canary-live --canary-work-item WORK_ITEM_ID
```

The canary gate requires:

- `--once`
- `--canary-live`
- `--canary-work-item ID`
- claim limit fixed to one job

The runtime reports `live_execution_enabled=true` only when the explicit canary
flag is used and the environment contains:

```bash
IGY6_WORKER_LIVE_CANARY=DIFF-148
```

## Side-Effect Posture

Actually executed in DIFF-148:

- argument parsing;
- config validation;
- canary safety gate validation;
- one-job queue/claim planning;
- structured canary status rendering.

Planned only in DIFF-148:

- PostgreSQL work item claim;
- PostgreSQL job-family writes;
- `audit_events` writes;
- artifact-store reads;
- Qdrant collection ensure and point upserts.

No real runtime data is mutated by DIFF-148 verification.

## Structured Results

The canary plan defines these result states for the future live executor:

- `claimed`
- `skipped`
- `completed`
- `failed`
- `unsupported`

## Runtime Posture

IGY6 remains Rust-primary with a Rust-native API path and retained
Python/Celery `worker` and `beat` services. Rust-only is not claimed.

Python/Celery remains required for production worker execution because real
Rust side-effect execution is not implemented in this DIFF.
