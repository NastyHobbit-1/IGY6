# DIFF-149: Rust Worker Live Side-Effect Executor

Status: Locked

## Type

Change-bearing Rust worker canary executor implementation.

## Objective

Implement real side-effect execution for exactly one explicitly selected Rust
worker canary work item while preserving safe non-mutating defaults and
retaining Python/Celery worker and beat as the production worker path.

## Gates

Live canary execution requires all of:

- `--once`
- `--canary-live`
- `--canary-work-item ID`
- `IGY6_WORKER_LIVE_CANARY=DIFF-148`

Without the environment acknowledgement, the command renders the non-mutating
canary plan.

## Implemented Side Effects

DIFF-149 implements these real side effects for the selected canary work item
only:

- PostgreSQL claim using `FOR UPDATE SKIP LOCKED`;
- `work_items` status/error updates for running, completed, and failed;
- `audit_events` for claim, start, success, and failure;
- artifact reads for `collection_normalization`, scoped under
  `IGY6_DATA_ROOT/artifacts`;
- `normalized_documents` writes for `collection_normalization`;
- `chunks` and `evidence_items` writes for `document_chunking`;
- chained follow-on `work_items` writes for document chunking and vector upsert;
- deterministic local vectors for `chunk_vector_upsert`;
- Qdrant collection ensure and point upsert for `chunk_vector_upsert`;
- chunk `embedding_status` and metadata updates after successful Qdrant upsert.

## Still Out Of Scope

- broad queue polling;
- processing more than one work item;
- long-running Rust worker process ownership;
- Docker Compose Rust worker service wiring;
- Python/Celery worker removal;
- Python/Celery beat removal;
- scheduler/beat replacement;
- Neo4j worker execution;
- full Rust-only runtime claim.

## Runtime Posture

IGY6 remains Rust-primary with a Rust-native API path and retained
Python/Celery worker and beat services. Rust-only is not claimed.

Python/Celery remains required because DIFF-149 is a controlled one-job canary,
not a process ownership cutover.

## Completion Notes

DIFF-149 adds a real side-effect canary executor, but production worker
ownership remains Python/Celery. The next DIFF should verify the canary against
controlled runtime data and decide whether to wire a long-running Rust worker
process or keep another staged canary phase.

Next recommended DIFF:
