# DIFF-150: Rust Worker Canary Verification Cutover Decision

Status: Locked

## Type

Facts-and-documentation cutover decision after DIFF-149.

## Objective

Verify whether the DIFF-149 Rust worker live side-effect canary executor is
ready for worker process cutover, then decide whether Python/Celery can be
removed or must remain the production worker path.

## Decision

Decision B: Rust worker process cutover is not ready.

Python/Celery `worker` and `beat` remain active. Docker Compose is unchanged.
`services/worker/` is retained. Full Rust-only runtime is not claimed.

## Canary Status

No real canary was run in DIFF-150.

Reason: no explicitly selected safe runtime work item was provided. DIFF-150
does not touch runtime/private data except through an explicitly scoped canary
verification, and broad queue processing is prohibited.

The non-mutating canary command remains valid for verification:

```bash
cargo run -p igy6-worker -- --once --canary-live --canary-work-item example-work-item
```

It does not execute side effects unless the environment also contains:

```bash
IGY6_WORKER_LIVE_CANARY=DIFF-148
```

## Verified Without Runtime Mutation

- DIFF-149 live execution remains gated by `--once`, `--canary-live`,
  `--canary-work-item ID`, and `IGY6_WORKER_LIVE_CANARY=DIFF-148`.
- Default `igy6-worker --check` remains non-mutating.
- `--dry-run --once` remains non-mutating.
- The non-env canary command renders a planned canary and remains non-mutating.
- Worker tests cover canary gate behavior, SQL claim shape with
  `FOR UPDATE SKIP LOCKED`, artifact path safety, Qdrant HTTP-origin bounds,
  and live result side-effect shape.
- Docker Compose still defines Python/Celery `worker` and `beat`.
- No Rust worker long-running Compose service is wired.

## Not Yet Verified By Real Canary

- PostgreSQL claim and status writes on a real selected `work_items` row.
- `audit_events` rows after a real selected canary.
- Artifact reads under `IGY6_DATA_ROOT/artifacts` for a real canary.
- `normalized_documents` writes from `collection_normalization`.
- `chunks` and `evidence_items` writes from `document_chunking`.
- Qdrant collection ensure and point upsert from `chunk_vector_upsert`.
- Chunk `embedding_status` and metadata updates after Qdrant success.
- Failure rollback posture against live runtime data.

## Remaining Blockers

- A controlled real canary must be run and audited against safe runtime data.
- Rust worker is not wired as a long-running worker process in Docker Compose.
- Broad queue polling is still not enabled.
- Only one explicitly selected canary work item is supported.
- Scheduler/beat posture is not replaced or formally retired.
- Production rollback after Rust process ownership is not verified.
